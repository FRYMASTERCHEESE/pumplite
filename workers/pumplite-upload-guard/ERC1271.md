# Base ERC-1271 guard verification

The production guard remains private (`workers_dev: false`). `ISSUE_ENABLED` is absent from production config and must equal the string `true` before issuance is allowed. No uploads, deployments or wallet connections are enabled by this change.

## Verification policy

Existing Base EOA personal_sign recovery is unchanged and runs first; a matching EOA signature needs no RPC. On failure, bounded contract signatures (0–512 bytes) are checked through ERC-1271. The digest is ethers.hashMessage of the existing canonical PumpLite challenge: audience, chain=base, subject, upload path/bytes/hash/image CID, issuedAt and nonce remain bound. Solana verification is unchanged.

Production config declares BASE_SIGNATURE_RPC bound to pumplite-base-signature-rpc. Contract verification requires that private binding by default. Only an absent binding plus the exact operator setting ALLOW_PUBLIC_BASE_RPC="true" permits the fixed https://mainnet.base.org public transport; production config keeps this false. A present malformed/failing binding is never bypassed, even with opt-in. Every contract verification checks chain ID 8453, obtains a block number, checks nonempty deployed code and calls isValidSignature(bytes32,bytes) at that same height. There is no cached approval, deployment transaction, arbitrary user-supplied RPC endpoint or automatic retry. Only the exact ABI-encoded bytes4 magic value 0x1626ba7e is accepted; reverts, missing code, malformed/wrong IDs, redirects and failed RPCs reject issuance. A trusted server-side BASE_SIGNATURE_RPC service binding may provide controlled read-only infrastructure; the binding is declared in source but has not been deployed or activated, and its chain responses are still verified.

Limits: 10 seconds total, 64 KiB per RPC response, four read-only calls, 500,000 gas eth_call budget. This resource policy can reject expensive/large-signature wallets; it is not a claim of universal wallet compatibility. ERC-6492 wrapped/counterfactual signatures are rejected and no factory deployment is attempted. The RPC is a trust dependency; chain ID is an identity check, not a cryptographic proof that an RPC is honest. Snapshotting by block height does not eliminate reorg risk. Contract signature validity is checked at issuance time; a short-lived grant already issued is not automatically revoked by later contract state changes.

Standard: https://eips.ethereum.org/EIPS/eip-1271 (reviewed 2026-09-28). The RPC returns an off-chain execution result, not a funded transaction. The guard continues to consume the challenge atomically, enforce quotas and reject replay through its existing Durable Object logic.

## Local verification only

Use the installed root dependencies. Wrangler 4.142.0 was executed from the npm tool cache; no dependency manifest or lockfile change is needed.

From this directory, run unit tests:

    node --test base-contract-identity-test.mjs service-binding-test.mjs

Run each existing non-e2e *-test.mjs with `node --import ./test-support/no-network.mjs FILE` to ensure unit suites never contact public providers. Existing Solana/EOA tests use their existing ephemeral in-memory test signing identities; no real wallet or stored signing material is read or printed. New ERC-1271 fixtures use no keys at all.

For local end-to-end tests, use three local terminals:

    node test-support/base-rpc.mjs
    npm exec --yes --package=wrangler@4.142.0 -- wrangler dev --local --ip 127.0.0.1 --port 8789 --config test-support/rpc-wrangler.jsonc
    npm exec --yes --package=wrangler@4.142.0 -- wrangler dev --local --ip 127.0.0.1 --port 8788 --config test-support/local-wrangler.jsonc --persist-to .wrangler/erc1271-test

The last config is TEST ONLY and enables issuance only in the local runtime. Never deploy either test config. The RPC fixture is a loopback EVM with zero accounts and injected pure runtime bytecode; there is no contract deployment/signing/transaction. Its synthetic signature is the expected digest, not a real wallet security scheme. The test traverses actual Worker, Durable Object SQL, ABI encoding and compiled EVM bytecode.

The local RPC fixture wraps the actual private signature RPC Worker and redirects only its fixed synthetic upstream to loopback; no public RPC is contacted. Run `node base-contract-lifecycle-e2e-test.mjs`, then all nine existing *-e2e-test.mjs scripts. Use fresh local persistence for repeat suites because quota tests deliberately consume quota. Stop the three local processes afterward.

Production-config bundle validation only:

    npm exec --yes --package=wrangler@4.142.0 -- wrangler deploy --dry-run --config wrangler.jsonc --outdir dry-run

The --dry-run flag is mandatory here. This task does not authorize deployment, a public issuance route, upload activation or live wallet acceptance. Mainnet smart-wallet provider compatibility and independent review remain external checks.
