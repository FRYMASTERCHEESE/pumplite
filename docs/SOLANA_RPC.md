# Solana RPC availability

Phantom account-access approval does not depend on public RPC availability. It grants no transaction approval. After connection, the UI separately reports Mainnet verification; all existing chain reads and transaction paths still verify the full configured genesis hash before proceeding. An unavailable RPC does not disconnect an otherwise valid account-access session.

The configured primary is https://pumplite-rpc.coreyedge123.workers.dev/rpc, with one fallback, https://solana-rpc.publicnode.com. The primary is a read-only Cloudflare proxy; its upstream credential is held privately in a Worker secret and must never appear in public configuration, source, generated assets or logs. The owner has confirmed a successful proxied response with the full Solana Mainnet genesis hash; this is not evidence of production capacity or funded transaction acceptance. Only genesis verification attempts the alternate endpoint after an RPC failure, at most once per check. The replacement becomes active only after its full Mainnet hash matches. An explicit wrong genesis fails immediately without fallback. No account query or transaction submission is automatically replayed. Existing 15-second per-request and response-size limits remain. Endpoint names and errors appear in the Phantom diagnostic.

PublicNode returned HTTP 200, the expected full Mainnet genesis hash and Access-Control-Allow-Origin: * during a read-only verification. This is not a guarantee of Android availability or production capacity. Before enabling trading, provision a browser-compatible, monitored production Mainnet RPC service (and independent fallback) with suitable quotas. Keep secret credentials on a controlled backend, never in public config. Update the exact CSP/header allowlist with endpoint changes; do not use wildcard network permissions. The proxy was deployed separately by the owner. This repository does not deploy or configure the Worker. Preserve its exact PumpLite origin restriction, read-only method allowlist, request limits, timeout and sanitized errors. Origin checks restrict browser access but are not authentication against non-browser clients; production rate limits, quota monitoring and abuse controls remain operational requirements. The proxy intentionally blocks transaction broadcasting. A separately reviewed submission path is required before any future trading activation; do not add write methods as part of RPC availability work.

References: https://solana.com/docs/tools/production-readiness and https://solana.publicnode.com/.
